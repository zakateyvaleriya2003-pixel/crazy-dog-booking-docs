# Требования к веб-системе Crazy Dog

## Назначение и границы

Система организует запись владельцев собак на занятия в одном кинологическом центре. Базовая версия охватывает профили питомцев, расписание, бронирование и отмену. Онлайн-оплата, абонементы и автоматические напоминания остаются за границами этой версии.

## Пользователи

Клиент управляет данными своих питомцев и своими записями. Кинолог просматривает назначенные ему занятия и необходимую для их проведения информацию о записанных питомцах. Администратор ведёт расписание и управляет записями центра; операции физического удаления важных данных не входят в его обычный сценарий.

## Функциональные требования

| Код | Требование | Критерий приёмки |
|---|---|---|
| FR-01 | Авторизация и разграничение доступа по ролям | Клиент не может получить или изменить чужую запись по прямой ссылке; кинолог видит только свои занятия |
| FR-02 | Создание и изменение карточки своего питомца | Клиент создаёт и изменяет только карточки своих питомцев. Кличка обязательна: после удаления пробелов по краям длина 1–60 символов; строка из пробелов отклоняется. Возраст задаётся необязательным целым числом полных месяцев не меньше 0. Порода и особенности необязательны. При нарушении правил сервер отклоняет сохранение и указывает поле с ошибкой. |
| FR-03 | Просмотр расписания и поиск занятия | Список показывает дату и время, вид занятия, кинолога, зал и свободные места. Фильтры по дате начала в часовом поясе центра и виду занятия применяются совместно по условию «И». Незаданный фильтр не ограничивает выборку; сброс снимает оба условия. Если совпадений нет, выводится «Занятия не найдены» и действие сброса фильтров. |
| FR-04 | Запись питомца на занятие | Клиент выбирает занятие, затем своего питомца и подтверждает данные; запись создаётся только после успешного сохранения |
| FR-05 | Проверка вместимости и повторной записи | При подтверждении система повторно проверяет наличие места; для одного питомца допускается не более одной активной записи на занятие |
| FR-06 | Отмена предстоящего бронирования | Владелец отменяет свою подтверждённую запись до начала занятия; статус меняется на «Отменена», место освобождается ровно один раз |
| FR-07 | Ведение расписания администратором | Администратор задаёт время начала и окончания, кинолога, зал, вид занятия и вместимость; пересечение времени одного зала или кинолога отклоняется |
| FR-08 | Просмотр списка участников кинологом | Кинолог видит участников только назначенного ему занятия; отменённые записи не входят в активный список |
| FR-09 | Обратная связь при сохранении | После отправки бронирования форма показывает «Сохранение» и блокирует повторное нажатие до ответа или обнаружения сетевой ошибки. Подтверждение с номером и статусом выводится только после ответа об успешном сохранении. При отказе сервера показана причина, ввод сохранён в текущей форме. Если ответ не получен, выводится «Результат не подтверждён» и предложение проверить «Мои записи». Повторный запрос не создаёт вторую активную запись того же питомца на то же занятие. |

| FR-10 | Завершение записи администратором | После окончания занятия администратор может перевести подтверждённую запись в «Завершена». До окончания занятия и для отменённой записи действие отклоняется. Клиент и кинолог не могут выполнить этот переход; повтор для завершённой записи не меняет её состояние |

## Нефункциональные требования

NFR-01. Интерфейс и сообщения об ошибках оформляются на русском языке.

NFR-02. Основной сценарий записи должен быть доступен при ширине экрана 360 пикселей без горизонтальной прокрутки страницы. Элементы управления остаются доступны с клавиатуры.

NFR-03. Проверки прав, вместимости и допустимых переходов статусов выполняются на сервере. Проверка только в интерфейсе не считается достаточной.

## Основные правила

Одна запись связывает одного питомца и одно занятие. Число подтверждённых записей не превышает вместимость занятия. Клиент может выбрать только своего питомца. При одновременной попытке занять последнее место подтверждается только одна запись. Время хранится однозначно и отображается в часовом поясе центра.

Статусы записи: «Подтверждена», «Отменена» и «Завершена». Статус «Завершена» проставляет администратор после проведения занятия. Отмена завершённой записи через клиентский сценарий недоступна. Состояние отправки формы не является статусом записи в базе.

Требования описывают проектируемую систему; результаты реализации и измерения производительности в этом документе не заявлены.
